# Full-text-first scientific summaries

The normal `build_pipeline()` path now defaults to safe full-text retrieval, PR #6 section-aware extraction/selection, and a six-section scientific summary. Set `FULL_TEXT_FIRST=false` before starting Python to reproduce the previous legacy paragraph workflow. This is an explicit migration of the production entry point; the reusable legacy builder and string-summary interfaces remain available.

## November 7 diagnosis

The saved local run contained nine featured records in `data/paper_sentences.json`, all explicitly marked `evidence_strategy=legacy`. Four arXiv records had `pdf_full_text` availability and five ChemRxiv records had `abstract_only`. The matching raw ChemRxiv records contained landing URLs but no `pdf_url`. The old downloader returned immediately when `pdf_url` was absent; it did not resolve ChemRxiv landing URLs or PubMed/PMC full text. Thus those five records never reached PDF parsing through that code path. The source feed's HTTP 403 diagnostics concern discovery, not proof that each paper's PDF was denied.

Even when an arXiv PDF was available, the old selector filled its summary slots from the abstract first. Its paragraph prompt asked for 2–3 sentences and cut evidence to 2,200 characters, then 1,200 on retry. PR #6 was installed but intentionally not enabled by default. Existing output did not record per-document download/extraction failures, so no additional historical parsing or budget failure can be inferred from it. None of the live run's data, caches, seen state or published HTML is replaced by this evaluation.

## Retrieval and identity

`evidence.full_text.retrieve_full_text()` returns `success`, `cached`, `unavailable`, or `failed`, with `paper_id`, `source_url`, SHA-256 `document_id`, a local `path`, `reason`, and stage-specific `attempts`. The path is removed from published summary metadata. Missing routes are distinct from access denial, invalid content and failed requests. Extraction separately reports `success`, `low_quality`, `failed`, or `unavailable`.

Supported routes are supplied PDFs on trusted public-source hosts; arXiv abstract-to-PDF routes; ChemRxiv DOI full-to-PDF routes; ChemRxiv landing metadata (`citation_pdf_url`); and PubMed-to-PMC ID resolution followed by licensed PMC public article metadata/PDF URLs. A landing page is never accepted as a PDF. An inaccessible route remains a reported failure, not a reason to bypass a paywall or anti-bot challenge. Unknown publisher hosts are deliberately unsupported rather than fetched indiscriminately.

PMC's legacy OA service was retired in August 2026. The implementation uses the public `pmc-oa-opendata` metadata listing and its `pdf_url`, with license metadata present, preferring an explicitly identified published article over an author manuscript. It does not assume the highest version is the newest published version. See [PMC's current access documentation](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/) and [the bucket schema](https://pmc-oa-opendata.s3.amazonaws.com/README.txt). Only PDF representations are currently parsed; a PMC record with XML/text but no public PDF remains unavailable through this adapter.

Requests use a restricted hostname set, public-address DNS checks, HTTP(S), no credentials or nonstandard ports, redirects revalidated at each hop, a five-hop limit, connect/read timeouts, and streaming byte limits (`MAX_PDF_BYTES`, default 25 MiB; metadata limited to 1 MiB). Ambient proxy credentials are disabled. Checks reduce SSRF exposure but do not implement DNS pinning against a compromised trusted host or protect a local cache from malicious filesystem writers.

New cache filenames hash the complete paper identity and include a metadata sidecar binding URL and content hash. Cache hits validate the signature, size and hash. Writes use same-directory staging and atomic replacement; an interrupted metadata write does not validate a mismatched PDF as a hit. Existing versioned arXiv cache files are reused read-only by exact ID to avoid redownloading the current cache. Their content hash is reported, but their prior download authenticity cannot be retrospectively proven. Other ambiguous old basename caches are not reused.

## Evidence, fallback and budgets

PR #6 retains page/block spans, conservative headings, numerical prose and captions, and excludes references and ambiguous numeric table blocks. It ranks Methods, validation, Results, limitations and complementary context, instead of taking the first characters of a PDF. See `scientific-evidence-extraction.md` for supported layouts, weights and limitations. The existing `EVIDENCE_CHAR_BUDGET` (3,600 default), `EVIDENCE_MAX_PASSAGES` (6) and `MAX_SUMMARY_CONTEXT_CHARS` ceiling remain in force. These are character limits on labeled evidence, not tokenizer guarantees; reserve model capacity for instructions and output.

`ABSTRACT_FALLBACK_POLICY=allow` permits a clearly labeled abstract-only featured summary. `brief_only` excludes it from featured generation. A full-text fallback reason distinguishes retrieval outcome, extraction failure/low quality, context-budget exclusions, poor heading detection, and empty full-text selection. These labels describe the observed stage and are not a claim that all alternative acquisition routes were exhausted. A valid PDF with only abstract text is not a full-text review.

Prepared availability stays in `evidence_mode`; actual selected input is recorded in `summary_input_evidence_mode`, while `summary_evidence_mode` describes the passages referenced by the retained summary sections (`pdf_full_text`, `abstract_only`, `unknown`). Referencing a passage is still not proof of its use or entailment. HTML labels these references unverified and warns that abstract-only output is not a comprehensive article review. `selected_passage_count`, `selected_source_sections`, `selected_evidence`, `selection_diagnostics`, `extraction_diagnostics`, `full_text_retrieval`, and `full_text_fallback_reason` remain machine-readable. The brief-only policy also preserves failure diagnostics in reference records.

## Summary contract and model transparency

`summary_format=scientific_sections` emits research question, methodology, key quantitative findings, validation/reliability, limitations, and relevance to computational drug discovery. Each entry contains `text` and `passage_ids`. The existing `tldr` is retained as Markdown with six headings for backwards-compatible HTML rendering and JSON consumers. Missing evidence is expressed as “Not established in the selected evidence.”

The LLM is instructed to preserve conditions, values, units, datasets and comparators and distinguish prediction/docking from experimental confirmation. The parser requires the six fields and valid supplied passage IDs. A basic new-number check suppresses a section introducing numbers absent from its referenced passages. **This is not a factual verifier:** reused numbers, incorrect units, distorted comparisons, missing qualifications and inappropriate significance statements can still pass. References remain candidate associations with `support_status=unverified`; no confidence or entailment score is invented.

The November 8 stabilization adds conservative number/unit-pair checks (including Unicode minus and common concentration/energy units), lexical protocol checks for validation prose, specific validation-detail checks, and denials for unsupported prospective/external/experimental/significance claims. Affected fields are withheld with explicit issue codes. These are necessary-support heuristics, not a claim of entailment: dataset/metric attribution, comparator scope, complex negation and scientific validity can still be wrong, and correct paraphrases can be withheld.

Malformed JSON or inference failure produces `extractive_fallback`: exact source passages under appropriate categories, explicitly prefixed “Source passage (unverified),” with unavailable categories marked not established. Invalid passage IDs now withhold only the affected generated section and record `unknown_passage_reference`; IDs are never guessed or silently repaired. If no substantive generated section remains, the result is extractive fallback. Empty evidence produces `unavailable`. Successful calls record the actual returned model, temperature and output cap; fallback extraction records no model as its generator. `attempted_model_identity` and `attempted_generation_parameters` separately retain the attempted call metadata. `withheld_sections` and HTML disclose suppressed generated fields. Existing string-returning Ollama calls remain compatible through a `str` subclass carrying call metadata.

The structured request permits 900 generated tokens by default. Existing model fallback behavior is retained; a shorter fallback-model token cap can yield invalid JSON and thus extractive fallback. No model-as-judge, cross-paper synthesis, table-cell reconstruction, OCR or factual-verification milestone is included.

## Real-paper evaluation

`python -m evaluation.full_text_replay --papers <manifest.json> --output <nonproduction-directory> --model mistral:latest` compares the same saved PDF and source abstract under legacy versus section-aware/structured generation. Set `PYTHONHASHSEED=0` and `HF_HUB_OFFLINE=1` for reproducible legacy hashed-embedding selection. The replay uses the same pinned model, temperature 0.2 and actual output cap of 900 for both formats; prompts necessarily differ. It never invokes publication or seen-state mutation. Repeated LLM output can still differ because this is a single stochastic generation per condition, not a statistical experiment.

Three real research articles were selected: molecular-property prediction (arXiv:2604.16123v1), active learning for formulation discovery including drug solubility (arXiv:2611.06394v1), and conditional molecular generation (arXiv:2604.11483v1). Two PDFs were already present locally; the active-learning PDF was downloaded into a temporary evaluation cache. Their article versions and content hashes are recorded. Selection is a convenience sample, not a representative scientific benchmark.

Reports retain per-paper summaries, candidate passages, source categories, quantitative-passage counts, page traceability and structural section counts. PR #5 is run against the saved outputs. There are no matching human-verified real-paper annotations: essential-finding coverage, factual quantitative accuracy, methodological specificity, unsupported-claim rate, limitations coverage and semantic completeness therefore remain `not_assessed`. Structural completion and increased full-text coverage must not be presented as proven scientific improvement. A domain reviewer must annotate the original sources before authoritative before/after scoring.

## Checkpointed recovery

Use an isolated directory such as `.evaluation-runs/` (excluded from Git and outside publication paths). Preserve original manifests, PDFs and results byte-for-byte with hashes before resuming. The November 8 recovery is recorded in `docs/full-text-evaluation-2026-11-08.md`; its local source artifacts live in `.evaluation-runs/fulltext-2026-11-08/`.

The replay skips existing completed conditions, including explicitly recorded invalid-output attempts. It checks paper identity and, where recorded, document hash, requested model and generation parameters. Historical records missing these fields retain their original bytes; their provenance and uncertainties must be recorded separately. Each new request checkpoints its exact prompt, raw response, model, parameters, timing and Ollama completion metadata before summary parsing. Resuming a raw-response checkpoint performs no new inference. There is at most one request per condition; a legacy compact-prompt retry does not trigger another generation.

An exclusive replay lock prevents concurrent invocations. Result publication uses a same-directory staged file and an exclusive hard link, so an existing result cannot be overwritten. This requires a filesystem supporting hard links (the local NTFS workspace does). An interrupted process may leave a lock or stage file; inspect these before removal. A network/server error records a failure and stops the replay, including HTTP 500; existing failure checkpoints block subsequent requests until explicitly reviewed. Invalid model output retains its raw response and records the production extractive fallback with `completed_invalid_output` and `structure_validated=false`, then permits evaluation of the next condition. Fallback text is never labeled a successful LLM summary.

After stabilization, a response with some invalid section references may retain its other accepted fields with `generation_mode=llm`; its `generation_issues`, `withheld_sections` and HTML warning explicitly disclose withheld fields. An all-rejected response or malformed response still falls back. `structure_validated` in replay artifacts describes mechanical contract acceptance, never scientific correctness.

Requests are pinned to the local loopback Ollama service, temperature 0.2 and a 900-token cap, with a 30-minute client timeout and no model fallback. A model tag does not prove byte-identical weights across sessions; save the installed model digest alongside the run. The larger timeout changes operational waiting behavior, not prompts or generation parameters. Per-condition JSON files are authoritative checkpoints; consolidated files are created only after the loop completes and are also never overwritten.

## Stabilized extraction and evidence budgets

Sparse `(cid:...)` font markers no longer invalidate an otherwise readable PDF. The adapter records marker count/density and retains raw text. Text with insufficient readable characters, a low alphabetic fraction, or more than 10% marker characters remains `low_quality`. Passages containing unresolved markers are excluded individually; no missing glyph or table value is guessed. The density threshold is a conservative heuristic, not a measured extraction-accuracy guarantee.

When no informative feed abstract exists, the section-aware builder uses abstract blocks in their page column and a next-page continuation up to a real heading/keyword label. The complete available abstract is retained on the prepared record. The legacy flat splitter now requires heading-like boundaries instead of stopping at prose words such as “methods.” Unusual reading order, inline headings and abstracts spanning more pages remain limitations. `available_abstract_chars` and `selected_abstract_chars` distinguish retained source text from budgeted context; selected characters do not measure semantic coverage.

Oversized PDF paragraphs are split at sentence ends under `EVIDENCE_PASSAGE_MAX_CHARS` (900 by default), preserving exact document offsets and source spans. Individual sentences are never cut solely to fit that size; oversized sentences may be excluded by the context budget. Selection prioritizes reported numerical Results and author-caveat coverage before Methods, under the existing 3,600-character/six-passage defaults. Explicit run-in Results/Limitations labels and a small heading-taxonomy extension cover observed cases. Section labels and keyword features remain heuristic. The updated workflow adds no dependencies and performs no factual reconstruction.
